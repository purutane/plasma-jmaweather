# 気象庁天気予報 (plasma-jmaweather)

気象庁の予報データをそのまま表示する KDE Plasma 6 用ウィジェットです。海外の気象サービス
を経由せず、`www.jma.go.jp` が配信している府県天気予報・週間天気予報を直接読みます。

> A KDE Plasma 6 applet showing the Japan Meteorological Agency forecast. Japanese regions only.

## できること

- **地域の自動判定** — 既定では接続元の IP アドレスから現在地を推定し、その地域の予報を出します。
  外れるときは「予報区」「地域」を手動で指定できます
- **パネル常駐** — 天気アイコンと気温（`29°/23°`）をパネルに表示。降水確率のみ、気温と降水確率の
  併記、アイコンのみにも切り替えられます
- **警報・注意報** — 選んでいる地域に発表中のものを展開表示の先頭に出します。パネルに印が
  付くのは警報以上のときだけで、注意報は展開表示にとどめます
- **クリックで展開** — 大きな天気アイコン、気象庁の天気文、最高最低気温、これからの降水確率
  （6時間ごと）、週間予報7日分、府県ごとの概況テキスト
- **全国 58 予報区 / 142 地域** に対応。「千葉県 - 北西部」のように予報区名を冠して表示します
- 中クリックまたは右クリックメニューで即時更新。既定の更新間隔は 30 分

## 動作環境

- KDE Plasma 6（Qt 6）
- ネットワーク接続。外部ライブラリや API キーは不要です

地域を自動判定するときだけ、接続元の IP アドレスを外部サービス（`get.geojs.io` / `ipwho.is`）に
問い合わせます。判定は 1 日 1 回で、結果は設定に保存して使い回します。手動指定に切り替えれば
`www.jma.go.jp` 以外とは通信しません。

## インストール

```sh
git clone https://github.com/purutane/plasma-jmaweather.git
cd plasma-jmaweather
kpackagetool6 --type Plasma/Applet --install .
```

更新するときは `--upgrade .` に変えて同じコマンドを実行します。削除は次の通りです。

```sh
kpackagetool6 --type Plasma/Applet --remove io.github.purutane.jmaweather
```

インストール後、ウィジェット一覧に出てこない場合は plasmashell を読み込み直してください。

```sh
kquitapp6 plasmashell && kstart plasmashell
```

あとはパネルを右クリック →「ウィジェットを追加」→「気象庁天気予報」を選びます。

### 開発時

編集したあとは上の `--upgrade` で入れ直し、plasmashell を読み込み直すと反映されます。
パネルに置かずに単体で起動して確認することもできます。

```sh
plasmawindowed io.github.purutane.jmaweather
```

テストは Node だけで動きます。`qmllint` があれば併せて実行されます。

```sh
node tests/run.js
```

解析ロジックの検証には気象庁の実データを使っています。取り直すときや、全国 56 配信分で
確かめたいときは次の通りです。

```sh
python3 tools/fetch_fixtures.py          # tests/fixtures/ を更新
python3 tools/fetch_fixtures.py --all    # 全国分（コミット対象外）
node tests/run.js --all
```

## 設定

ウィジェットを右クリック →「気象庁天気予報を設定」から変更できます。

| 項目 | 内容 |
| --- | --- |
| 地域の決め方 | 自動判定（既定） / 手動で選ぶ |
| 予報区 / 地域 | 全国 58 予報区とその一次細分区域 |
| パネルの表示 | アイコンのみ / 気温 / 降水確率 / 気温と降水確率 |
| 地域名 | パネルにも地域名を併記するか |
| 警報・注意報 | 発表中のものを表示するか（既定は表示する） |
| 更新間隔 | 5〜360 分（既定 30 分） |

自動判定は設定画面の「再判定」か、右クリックメニューの「現在地を判定し直す」でやり直せます。
1.0 から更新した場合、既に地域を選んでいた設定はそのまま手動指定として残ります。

## データについて

出典は気象庁です。`bosai` 配下の JSON をそのまま読んでいます。

- 府県天気予報: `https://www.jma.go.jp/bosai/forecast/data/forecast/{予報区コード}.json`
- 府県概況: `https://www.jma.go.jp/bosai/forecast/data/overview_forecast/{予報区コード}.json`
- 気象警報・注意報: `https://www.jma.go.jp/bosai/warning/data/warning/{予報区コード}.json`
- 予報区一覧: `https://www.jma.go.jp/bosai/common/const/area.json`
- 市区町村の外接矩形: `https://www.jma.go.jp/bosai/common/const/class20relm.json`（現在地の逆引き用）

短期予報は 1 日 3 回（5時・11時・17時頃）、週間予報は 1 日 2 回更新されます。それより短い間隔で
取りに行っても内容は変わりません。警報・注意報は随時更新されるので、更新間隔をそのまま反映
します（既定 30 分なので、発表から表示までは最大でその分だけ遅れます）。

これらは気象庁のウェブサイトが内部的に使っているもので、仕様が公表された API ではありません。
予告なく形式が変わる可能性があります。利用にあたっては
[気象庁ホームページについて](https://www.jma.go.jp/jma/kishou/info/coment.html) を確認してください。

`contents/code/` の 4 つの生成物と `tests/fixtures/` の JSON は、上記から取得した気象庁のデータを
含みます（出典: 気象庁）。MIT ライセンスの対象は本ウィジェットのコードです。

## 実装メモ

気象庁の JSON は素直に読めない箇所があり、全国分の実データで確認しながら対応させています。

- **週間予報は区域のくくりが粗い** — 短期予報の「中通り」「浜通り」が週間では「中通り・浜通り」に
  まとまるなど、149 区域中 133 件でコードが一致しません。単純に並び順で対応させると根室・浜通り・
  伊豆諸島南部・大隅・種子島屋久島の 5 箇所が別地域の予報を拾ってしまうため、「短期側に存在しない
  コードを持つ週間区域＝受け皿」へ寄せています。全 58 予報区で受け皿が一意に定まることを確認済みです
- **気温は観測所単位** — 短期予報の気温は天気の区域と数が合いません（福島県は 3 区域に対し 7 観測所）。
  週間予報側の観測所コードが短期側にも必ず存在することを利用して、そこを鍵に引いています
- **配信コードの例外** — 十勝 (014030) と奄美 (460040) は `area.json` のコードでは 404 になるため、
  それぞれ 014100 / 460100 へ読み替えます
- **夕方以降は今日の気温が消える** — 17 時発表以降、今日の最高・最低気温は配信対象から外れます。
  その場合は主表示を翌日に繰り上げ、見出しに「明日」と出します
- **天気コード** — 気象庁の 118 コードを Breeze の天気アイコンへ対応させています。夜間は今日を
  表示しているときだけ夜アイコンに切り替わります
- **現在地は市区町村の最近傍で決める** — 気象庁は一次細分区域の境界を配信していないため、
  警報図が使っている市区町村 1805 件の外接矩形（`class20relm.json`）の中心を代表点として並べ、
  IP から得た座標に一番近いものが属する区域を選んでいます。最近傍が 100km より遠ければ
  国外とみなして手動指定へ落とします（蓋が無いとソウルから対馬を拾います）
- **飛び地を持つ市区町村は代表点を名指しする** — 小笠原村は南鳥島と沖ノ鳥島まで市域に含むため
  矩形の対角が 2000km 近くあり、中心は海の上に落ちます。久米島町・石垣市・隠岐の島町・北大東村・
  十島村も同様なので、有人島の位置を `tools/generate_data.py` の `ISLAND_POINTS` に書いています。
  新しい飛び地が出てきたら生成時にエラーで止まります
- **警報だけは予報区コードを読み替えない** — 予報で 404 になる十勝 (014030)・奄美 (460040) は、
  警報だと自分のコードでそのまま配信されています。しかも読み替え先の 014100 / 460100 の警報 JSON に
  その地域は入っていないため、予報と同じ感覚で `Areas.endpoint()` を通すと、この 2 地域だけ警報が
  永久に出なくなります。区域コードは `areaTypes[0]` が一次細分区域そのもので、全 58 予報区 142 地域が
  対応する予報区の JSON に含まれることを確認済みです
- **解除された警報も同じ配列に残る** — `status` が「解除」のものが混ざり、実データでは発表中より
  多いことすらあります。落とさずに並べると解除済みばかりが表示されます。コードを持たない
  「発表警報・注意報はなし」も同じ配列に来るので、これも目印として落とします
- **警報コードの表は配信されていない** — 天気コードと違って `const` 配下に無く、警報ページの
  インラインスクリプトが唯一の出どころです（警報・注意報の 36 コード）。そのページは洪水を「氾濫」と
  呼び替えて別配信から描いているため表から洪水が抜けており、`tools/generate_data.py` の `WARN_EXTRA` で
  補っています。表に無いコードは捨てずに警報として扱い、コード番号のまま表示します。黙って
  落とすと、気象庁がコードを増やした日に特別警報を出し損ねるためです
- **見出しの文は予報区全体のもの** — `headlineText` は「伊豆諸島南部では…」のように他の地域の話が
  混ざるので、主役は地域別の警報名にして、見出しはその添え物として出しています
- **IP からの判定はよく外れる** — 日本の回線は契約者の登録地（多くは東京）に丸められることがあり、
  同じ回線でもサービスによって県が変わります。だから手動指定を残してあり、自動判定に失敗したときは
  展開表示にその旨を出します

## データファイルの再生成

`contents/code/` の `Areas.js`・`Telops.js`・`Geo.js`・`WarnCodes.js` は気象庁のサイトから
生成したものです。区域の再編や天気コード・警報コードの追加があったときは次を実行します。

```sh
python3 tools/generate_data.py
```
